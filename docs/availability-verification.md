# Cynapx 99.9% 가동률(Availability) 검증 보고서

> **작성**: 2026-07-16 / **기준 커밋**: `76d8e7b` + AV-1/AV-2 수정 반영 / **검증 도구**: 소크·폴트-인젝션 프로브(90s), SIGKILL MTTR 측정(3회), supertest 게이트
>
> **요구사항**: "기능 안정성의 99.9% 가동률" (사업관리 관행 기준, three nines)
> **검증 질문**: Cynapx가 이와 비슷한 수준을 *만족할 수 있는가* — 그리고 그 전제조건은 무엇인가.

---

## 0. 결론 요약

**조건부 달성 가능 (Yes, with operational preconditions).**

- **요청-레벨 안정성**: 실측에서 유효 요청 성공률 **100%**(90/90), 폴트 인젝션 30/30 전량 올바른 4xx 처리(수정 후), 파일 시스템 churn(깨진 소스 포함) 중 프로세스 생존 — 요청-레벨에서 0.1% 오류 예산을 위협하는 경로는 발견되지 않았다.
- **프로세스-레벨 가용성**: 크래시 복구(MTTR)가 **0.7~2.7초**로 실측되어, **supervisor 자동 재기동이 전제되면** 99.9%(월 43.8분 예산)는 산술적으로 넉넉히 달성 가능하다 — 3초 MTTR 기준 **월 ~875회 크래시**까지 예산 내다.
- **supervisor 없이는 달성 불가**: `uncaughtException`은 설계상 `process.exit(1)`로 종료한다(복구 불가 상태에서 좀비로 사는 것보다 옳은 설계). 재기동 주체가 없으면 첫 크래시가 곧 무한 다운타임이다. → §4 운영 전제조건 필수.
- **이번 검증에서 가용성 결함 2건을 발견·수정했다**(§3). 둘 다 "정상 부하가 가용성 사고로 오판되는" 경로였다.

## 1. 가용성 모델 정의

Cynapx는 self-hosted 단일 인스턴스 도구다. SaaS식 다중화가 아니라 **단일 프로세스 + supervisor 재기동** 모델로 가용성을 정의한다.

| 항목 | 정의 |
|------|------|
| 가용성 표면 | 장수 프로세스인 **REST API 서버**(`--api`) 및 MCP HTTP 트랜스포트. (stdio MCP 모드는 클라이언트 세션에 수명이 종속되므로 SLO 대상이 아님) |
| SLI-1 (liveness) | `/healthz`가 200을 반환하는 시간 비율 |
| SLI-2 (request success) | 유효 요청 중 5xx/연결 실패가 아닌 비율 |
| SLO | 99.9% — 허용 다운타임 **월 43.8분 / 연 8.76시간** |
| 산술 | 가용성 = MTBF / (MTBF + MTTR). MTTR 실측 ≈ 3s(보수) → 99.9% 위반에는 월 875회 이상의 크래시 필요 |

## 3. 이번 검증에서 발견·수정한 가용성 결함

### AV-1 — `/healthz`가 레이트리미터에 종속 (수정: limiter `skip`)

- **결함**: `globalLimiter`(IP당 100req/분)가 `/healthz`에도 적용됐다. Docker/k8s 프로브는 로컬 에이전트 트래픽과 IP를 공유하므로, **분당 100요청 이상의 정상 부하만으로 프로브가 429**를 받는다. Dockerfile HEALTHCHECK는 `statusCode === 200`만 healthy로 보므로 3회 재시도(~90초) 후 **정상 인스턴스가 unhealthy 판정 → 오케스트레이터 재시작 루프**.
- **실측 입증**: 미수정 빌드에서 동일 IP 105요청 후 `/healthz` → **HTTP 429** 재현.
- **수정 검증**: 수정 빌드에서 동일 시나리오 → API는 429, `/healthz`는 **200 유지**. supertest 게이트 추가.

### AV-2 — 클라이언트 폴트가 5xx로 유출 (수정: 에러 핸들러 4xx 매핑)

- **결함**: 악성 JSON·1MB 초과 바디가 body-parser에서 거부될 때 catch-all 핸들러가 **500**으로 응답 — 클라이언트 잘못이 서버 장애로 보고되어 **5xx 기반 가용성 SLI를 오염**시킨다(모니터링이 가짜 장애로 발화).
- **실측 입증**: 폴트 인젝션 30건 중 10건(malformed-json 5, oversized-body 5)이 500 유출.
- **수정 검증**: body-parser 오류의 4xx `status`를 존중하도록 수정 → 재실측 **30/30 전량 4xx**(400/413). supertest 게이트 추가.

## 4. 동적 검증 — 실측 결과

**환경**: 빌드된 `dist/bootstrap.js --api`, 픽스처 프로젝트(TS), `CYNAPX_EMBED_PROVIDER=null`, 로컬 루프백.

### 4.1 소크 + 폴트 인젝션 (90초, 수정 반영 후)

| 지표 | 결과 |
|------|------|
| `/healthz` 연속성 (250ms 간격) | **357/357 = 100.000%** (non-200: 0, 연결오류: 0), p50 1.8ms / p99 32.3ms |
| 유효 요청 성공률 (1req/s, 3개 엔드포인트 순환) | **90/90 = 100.000%** (5xx: 0, 연결오류: 0), p50 2.6ms / p99 19.4ms |
| 폴트 인젝션 (6종 × 5회: 악성 JSON/오버사이즈/오인증/미지 라우트/잘못된 메서드/타입 혼동) | **30/30 올바른 4xx** (5xx 유출 0, 연결오류 0) |
| 파일 churn (5s 간격 수정 + 항상-깨진 소스 파일 생성/삭제, 총 36 write) | 프로세스 생존, healthz 200 유지, 인덱싱 지속 |

### 4.2 크래시 복구 (MTTR)

`SIGKILL` 후 재기동 → `/healthz` 200까지:

| 트라이얼 | 시간 |
|----------|------|
| 1 (콜드, 락 승계 포함) | 2,715 ms |
| 2 | 827 ms |
| 3 | 706 ms |

→ **MTTR ≈ 0.7~2.7초**. SIGKILL로 남은 stale 락도 재기동을 막지 않음(락 승계 정상).

### 4.3 SLO 산술

- 99.9% = 월 2,628초 다운타임 예산.
- supervisor 즉시 재기동 가정, 보수적 MTTR 3초: **크래시 875회/월**(≈29회/일)까지 예산 내.
- 실측 소크에서 크래시 0회 — 도달 여유가 매우 크다.

## 5. 운영 전제조건 (이것 없이는 99.9% 불가)

1. **자동 재기동 supervisor** — 다음 중 하나 필수:
   - Docker: `docker run --restart=always ...` (HEALTHCHECK는 이미 이미지에 배선됨)
   - Kubernetes: liveness probe → `/healthz` (restartPolicy 기본값으로 충분)
   - systemd: `Restart=always`, `RestartSec=1`
2. **`KNOWLEDGE_TOOL_TOKEN` 고정 주입** — 미설정 시 자동 생성되지만, 재기동 간 토큰 연속성은 운영자가 보장해야 클라이언트 재연결이 끊기지 않는다.
3. **모니터링 SLI는 5xx + 연결오류 기준** — AV-2 수정으로 클라이언트 폴트가 SLI를 오염시키지 않는다.

## 7. 재현 방법

소크·폴트-인젝션 프로브와 MTTR 측정은 스크립트로 재현 가능하다:

```bash
# 서버 기동 (픽스처 프로젝트에 .cynapx-config 앵커 필요)
KNOWLEDGE_TOOL_TOKEN=<token> CYNAPX_EMBED_PROVIDER=null \
  node dist/bootstrap.js -p <project> --api --api-port 3777

# 소크: healthz 250ms 간격 + 유효 1req/s + 폴트 6종 20/min + 파일 churn 90s
# (scripts/availability-probe.mjs — 본 보고서의 부속 스크립트)

# MTTR: kill -9 <pid> 후 재기동 → /healthz 200까지 시간 측정
```

**게이트**: `tests/api-server-ratelimit-healthz.test.ts`가 AV-1/AV-2를 회귀 방지한다 (vitest 882/882 그린).
